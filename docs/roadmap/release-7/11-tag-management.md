# Add a tag management page
<!-- labels: enhancement,priority: P2,area: workflow -->

## Problem

The `Tag` entity exists, participates in `SearchService` matching, and is rendered as filter chips on the search page. But there is no Tags page anywhere in `Brainy.Web/Components/Pages`. Tags can be created and attached, never renamed, merged or deleted.

The result is one-way growth: a typo'd tag is permanent, `meeting` and `meetings` coexist forever, and the tag filter bar degrades as the vault grows. This is exactly the "maintaining a knowledge system" burden Brainy positions against.

## Scope

- Tag list page with usage counts and last-used date.
- Rename, merge and delete, with the affected-note count shown before confirming.
- Find unused tags and bulk-remove them.
- Navigate from a tag to its tagged items.

## Guardrails

- User-scoped throughout — `SearchService` already scopes tag matching by `UserId` and that must hold here.
- Merge and delete are destructive: confirm with an accurate impact count first.
- Invalidate the relevant cache tags on mutation, following the existing tag-based invalidation added in 5.13.2.

## Acceptance criteria

- [ ] Renaming a tag updates every note using it.
- [ ] Merging two tags preserves all associations and removes the source tag.
- [ ] Deleting a tag detaches it without deleting notes.
- [ ] Usage counts are accurate and cached results do not go stale after a mutation.
