# Add per-user bring-your-own AI provider key
<!-- labels: enhancement,priority: P0,area: commercial,area: trust,area: platform -->

## Problem

`PlanCatalog` declares `AllowsBringYourOwnKey: true` on both Starter and Pro, documented as *"a safe default that does not contradict any published pricing claim"*. The same XML comment then states: *"This flag is the entitlement-matrix declaration only — actual per-user key storage/UI is not implemented in this change."*

So BYOK is a marketed entitlement with no implementation. Today `AddAiAssistant` resolves one process-wide `IChatClient` from `AiAssistantOptions` at startup; there is no per-user resolution path at all.

This is also what makes AI affordable: Starter users get `AiAvailable: false` and no route to AI whatsoever, while every Pro request is billed to the host.

## Scope

- Per-user encrypted storage of an AI provider key (provider, key, model/deployment), scoped to the authenticated user like every other entity.
- Key management UI on the Plan and usage screen in `Manage.razor`, alongside the existing plan matrix rendering.
- Per-request `IChatClient` resolution: user key when present, hosted client otherwise, `NullAiAssistant` when neither applies.
- BYOK requests bypass hosted metering entirely (see the metering issue in this epic).
- Validate a key with a cheap probe call before saving, and show provider/model/data-boundary implications before first use.

## Guardrails

- Keys encrypted at rest, never logged, never returned to the client after save, never included in the data export.
- A user's key is never used to serve another user's request.
- Deleting the account or the key removes it immediately, consistent with the existing account-deletion cache invalidation.

## Acceptance criteria

- [ ] A Starter user with their own key can use AI features; without one they cannot.
- [ ] An invalid key is rejected at save time with a clear message.
- [ ] Key material does not appear in logs, the JSON export, or any API response.
- [ ] Tests cover user isolation, fallback ordering, and revocation.
