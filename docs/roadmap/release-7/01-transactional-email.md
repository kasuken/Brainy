# Add transactional email delivery
<!-- labels: enhancement,priority: P0,area: platform,area: trust -->

## Problem

Brainy cannot send a single email. There is no `IEmailSender` implementation, no `SmtpClient`, and no SendGrid or MailKit package anywhere in the solution. ASP.NET Core Identity exposes `Identity:RequireConfirmedAccount` as a configuration switch, but nothing can deliver a confirmation message, so enabling it would lock users out. Password reset is equally undeliverable.

This blocks account confirmation, password recovery, billing receipts (#2 in this epic), deadline reminders and any digest.

## Scope

- Implement `IEmailSender` / `IEmailSender<ApplicationUser>` against a configurable provider, following the existing options pattern used by `AiAssistantOptions` and `BillingOptions`.
- Add an `EmailOptions` section with a `None` default that logs instead of sending, matching how `AiProviderType.None` and `NullBillingProvider` behave today.
- Cover password reset and email confirmation flows end to end.
- Templated, plain-text-plus-HTML messages with the Brainy sender identity used on the marketing pages.
- Respect the rate limiter already configured in `Program.cs` for account endpoints.

## Guardrails

- A missing or misconfigured provider must fail closed and visibly, never silently drop mail.
- No user content in email subject lines beyond what the user themselves entered.
- Provider credentials come from configuration or User Secrets, never committed.

## Acceptance criteria

- [ ] `Email:Provider=None` starts the app and logs outbound messages without attempting delivery.
- [ ] A configured provider delivers password reset and confirmation mail.
- [ ] `Identity:RequireConfirmedAccount=true` produces a working registration flow.
- [ ] Tests cover the null provider, template rendering, and that send failures surface as errors rather than silent no-ops.
