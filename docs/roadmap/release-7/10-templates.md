# Add templates for projects, notes and outputs
<!-- labels: enhancement,priority: P1,area: workflow -->

## Problem

Nothing template-shaped exists in the domain. Every recurring piece of work — a weekly client report, a meeting note, a new consulting engagement with its standard task list — is rebuilt by hand each time. For a product positioned around turning captured information into useful work without maintaining a system, making people retype their own structure is the wrong kind of friction.

## Scope

- Project templates: name pattern, default task list with relative due dates, default area and goal linkage.
- Note templates: title pattern and content scaffold.
- Output templates: type, structure and default source selection.
- Create-from-template entry points on the existing creation flows.
- Save any existing project, note or output as a template.
- A small built-in starter set so the feature is useful on day one.

## Guardrails

- Templates are user-scoped and count against no entitlement limit themselves; instantiating one is subject to the normal project limits enforced by `EntitlementService`.
- Instantiation is a plain create — no hidden linkage that makes the resulting entities behave differently from hand-made ones.
- Relative due dates resolve against the user's calendar date, not UTC.
- Included in export, import and account deletion.

## Acceptance criteria

- [ ] A project template instantiates with tasks and correctly offset due dates.
- [ ] An existing project can be saved as a template.
- [ ] A Starter user at their project limit is blocked at instantiation with the normal upgrade message.
- [ ] Templates round-trip through export and import.
