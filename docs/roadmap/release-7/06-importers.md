# Add importers for Obsidian, Notion, Markdown and Evernote
<!-- labels: enhancement,priority: P1,area: capture,area: onboarding -->

## Problem

`IDataImportService` only accepts Brainy's own versioned JSON export. That makes it a backup-restore tool, not an onboarding path. Someone arriving from Obsidian or Notion — exactly the audience #293 describes as finding "Notion too broad or Obsidian too maintenance-heavy" — has to retype everything, so they never reach a first capture-to-focus loop.

## Scope

- Obsidian vault import: folder of Markdown, front matter, `[[wiki links]]` mapped onto `NoteRelationship`, tags mapped onto `Tag`.
- Notion export import (Markdown + CSV zip), mapping databases onto Projects or Resources where the shape allows.
- Generic Markdown folder import.
- Evernote `.enex` import.
- Preview before commit, reusing the existing `PreviewImportAsync` pattern that reports creates, reuses and skips per entity type.
- Map imported items into the Inbox by default rather than guessing a PARA category, so the user processes them deliberately.

## Guardrails

- Transactional, like the existing import: the whole import commits or none of it does.
- Re-importing the same source must not duplicate data.
- Never fabricate structure the source did not contain. Unmappable content lands in the Inbox, not a guessed category.
- Attachments that cannot be imported are reported, not silently dropped.

## Acceptance criteria

- [ ] An Obsidian vault imports with links and tags preserved.
- [ ] Preview reports accurate per-type counts before anything is written.
- [ ] A repeated import of the same archive is a no-op.
- [ ] Malformed, oversized and adversarial archives (zip traversal, symlinks) are rejected safely.
- [ ] Tests cover user isolation and transactional rollback on partial failure.
