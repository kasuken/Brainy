# Decide and enforce hosted AI metering
<!-- labels: enhancement,priority: P0,area: commercial,area: trust -->

## Problem

`PlanCatalog` ships Pro with `AiAllowancePerPeriod: null`, meaning unlimited. The XML comment is explicit that this is a placeholder for an unmade decision:

> Whether hosted AI should be metered at all is an explicit open question in issue #296 ("Decision needed: ... whether hosted AI is metered"); until that is decided, Pro defaults to unlimited (null) rather than a fabricated numeric cap, so this file does not silently assert an unmade business decision. Set a finite value here once that decision ships.

At $2/month billed yearly, one heavy user running output generation over long notes can exceed the plan's entire annual revenue in a week. The `AiAllowanceStatus` DTO already exists but has no finite limit to report against.

## Scope

- Make the call: finite Pro allowance, unlimited-with-fair-use, or hosted AI available only via BYOK.
- Set `AiAllowancePerPeriod` to a real value and enforce it in `EntitlementService`.
- Surface remaining allowance and reset date on the Plan and usage screen.
- Graceful degradation at the cap: clear message, BYOK as the offered route, never a silent failure.
- Update the `/pricing` page and AI transparency page to match whatever is decided.

## Guardrails

- BYOK requests must not consume hosted allowance.
- Published pricing copy and enforced entitlement must agree — the plan matrix is the single source of truth and is rendered to users.
- Counting happens server-side; the client cannot influence the meter.

## Acceptance criteria

- [ ] A finite allowance is enforced and a user at the cap gets an actionable message.
- [ ] Remaining allowance and reset date are visible before the user hits the cap.
- [ ] BYOK usage does not decrement the hosted counter.
- [ ] `/pricing`, the AI transparency page and `PlanCatalog` state the same limits.
- [ ] Tests cover boundary behaviour at and just under the cap, and the rolling window reset.
