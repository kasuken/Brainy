# Epic: Brainy 7.0 — a Brainy you can buy, and a Brainy that finds things
<!-- labels: enhancement,epic,priority: P0 -->

## Outcome

Version 6.0.0 landed the operational foundations: offline capture, guided weekly review, resume context, trust pages, product analytics, and plan/entitlement definitions. What it did not land is everything that turns those foundations into a product someone can pay for and rely on to find things again.

Release 7 closes that gap along two axes:

1. **Commercial and trust readiness** — Brainy can actually be bought, AI cost is bounded, and the app can send an email.
2. **Retrieval and AI depth** — a user finds what they captured by concept, not by remembering the exact wording, and the AI abstraction already in the codebase is actually wired into the workflow.

This epic is a **candidate backlog for triage**, not a committed scope. Sub-issues are grouped by tier; priority labels reflect the proposed ordering, not a decision.

## Evidence this epic is based on

A full audit of the repository at `6.0.0` (472 source files, 41 application services, 125 Razor components, 4 HTTP endpoint groups):

- `SearchService.cs` search is lexical only — the code comment at the query site states *"EF Core translates String.Contains to LIKE '%term%'"*. No full-text index, no fuzzy matching, no concept recall.
- There is **no email sender anywhere in the solution** — no `IEmailSender`, `SmtpClient`, SendGrid, or MailKit reference. `Identity:RequireConfirmedAccount` is configurable but nothing can deliver the mail.
- `NullBillingProvider` is the only `IBillingProvider` implementation; checkout returns *"No payment provider is configured yet. Contact us to upgrade."* Pro is not purchasable.
- `PlanCatalog` declares `AllowsBringYourOwnKey: true` on every tier, with an in-code note that *"actual per-user key storage/UI is not implemented in this change"*.
- `PlanCatalog` ships Pro with `AiAllowancePerPeriod: null` (unlimited), with an in-code note that whether hosted AI is metered is an explicit open decision.
- `IAiAssistant` exposes five operations; `SuggestParaClassificationAsync` and `DetectDuplicatesAsync` have **no call sites** — meanwhile `InboxSuggestionsService` classifies notes with a hardcoded keyword list.
- `IDataImportService` only re-imports Brainy's own JSON export — there is no migration path from an existing vault.
- No note revision history entity, no tag management page, no localization infrastructure, no Playwright/E2E coverage, no OpenTelemetry.

## Proposed tiers

### Tier 1 — release blockers
Transactional email, a real billing provider, hybrid search, per-user BYOK keys, and an actual AI metering decision. Without these, v7 is v6 with more workflow.

### Tier 2 — core loop leverage
Wiring the existing AI surface, document capture with OCR, importers from other tools, note version history, calendar/reminder egress, web push, and templates.

### Tier 3 — polish and platform
Tag management, command palette, output share links, Markdown export, E2E tests, observability, localization, and activation metrics.

## Guardrails

Carried forward unchanged from #292:

- Preserve the solo-first, user-scoped architecture. Every read and mutation stays scoped to the authenticated user.
- Keep AI opt-in, scoped, source-backed and reviewable. AI-generated values stay separable from user edits.
- Do **not** build a graph view, a plugin marketplace, a generic vault chatbot, a team workspace, or a gamified productivity system. The one adjacent item in this epic that touches sharing (read-only Output links) is deliberately scoped to a single published deliverable and must not grow into collaboration.

## Success measures

- Pro can be purchased end to end without manual intervention.
- Hosted AI spend per user is bounded and visible to the user.
- A user finds a note by describing its concept rather than its title.
- A user arriving from Obsidian or Notion reaches their first captured-to-focus loop without retyping their content.
