# Add read-only share links for Outputs
<!-- labels: enhancement,priority: P2,area: workflow,area: trust -->

## Problem

Outputs are the payoff of the whole CODE loop — the point where stored knowledge becomes a deliverable. They are also the one thing a user would want to send to somebody else, and they are locked behind authentication with only copy and download as escape hatches.

## Scope

- Per-output, opt-in, tokenised public URL rendering the Markdown read-only.
- Revoke at any time; optional expiry.
- Minimal public view on the existing marketing layout, `noindex` by default.
- Visible indicator on the output detail page when a share link is active.

## Guardrails — read this before implementing

**This must not become collaboration.** #292 explicitly rules out a team workspace, and this issue is deliberately the narrowest possible version of sharing: one output, read-only, no comments, no accounts, no permissions model, no notion of a recipient. If the design starts needing invitations, roles or membership, stop and close this issue instead.

- Tokens are unguessable and revocable, and reveal nothing about the owner or their other data.
- The shared page exposes only the output's own content — no project, task, note or user metadata.
- Sharing is per-output and off by default. Never a bulk or account-level toggle.
- `noindex` unless the user deliberately opts into indexing.

## Acceptance criteria

- [ ] An output can be shared, opened anonymously, and revoked.
- [ ] A revoked or expired link returns a clean 404.
- [ ] The public page leaks no data beyond the output content itself.
- [ ] Security tests cover token guessing, revocation and cross-user access.
