# Implement a real billing provider so Pro is purchasable
<!-- labels: enhancement,priority: P0,area: commercial -->

## Problem

`NullBillingProvider` is the only `IBillingProvider` implementation. `CreateCheckoutSessionAsync` returns *"No payment provider is configured yet. Contact us to upgrade."*, `CreatePortalSessionAsync` does the same, and webhook signature verification always fails. The `/pricing` page markets Pro at "$2 / month, billed yearly" with no way to buy it, and plan changes are only possible through the internal `IEntitlementService.SetPlanTierAsync` path.

The seam is already clean — `NullBillingProvider`'s own remarks state a real implementation is a drop-in replacement that requires no other changes to the entitlement system.

## Scope

- Implement `IBillingProvider` against the chosen provider (Stripe or Paddle) and select it in `DependencyInjection.AddBilling` from `BillingOptions.Provider`.
- Hosted checkout and customer portal sessions.
- Real webhook signature verification wired into the existing `BillingWebhookEndpoints`.
- Upgrade, downgrade, cancellation and payment-failure transitions mapped onto `PlanTier`, reusing the existing downgrade-to-read-only project handling.
- Receipts and dunning mail (depends on transactional email).

## Existing work to build on, not duplicate

`ProcessedWebhookEvent` and `BillingWebhookProcessor` already provide idempotent webhook handling with test coverage in `BillingWebhookProcessorTests`. `FakeBillingProvider` already exists for tests.

## Guardrails

- Webhook endpoints stay unauthenticated but signature-verified; an unverified payload must never apply a plan change.
- Provider keys and webhook secrets from configuration only.
- Keep `NullBillingProvider` as the default so local development and self-hosting still work.

## Decision needed

Which provider. Paddle acts as merchant of record and handles EU VAT, which matters for a Swiss-operated product selling into the EU; Stripe has the better .NET SDK and lower fees but leaves tax registration to you.

## Acceptance criteria

- [ ] A Starter user can complete checkout and is Pro immediately afterwards.
- [ ] A Pro user can open the portal and cancel; entitlement reverts at period end.
- [ ] A forged webhook payload is rejected and changes nothing.
- [ ] Replayed webhook events remain idempotent.
- [ ] `Billing:Provider=None` still starts and behaves exactly as today.
