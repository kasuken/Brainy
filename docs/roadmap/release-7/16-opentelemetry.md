# Add OpenTelemetry traces, metrics and logs
<!-- labels: enhancement,priority: P2,area: platform -->

## Problem

`Program.cs` configures health checks (`/health/live`, `/health/ready`) and a partitioned rate limiter, which covers whether the app is up. It does not cover whether the app is *working*. There is no OpenTelemetry instrumentation anywhere.

Version 6.0.0 added flows that fail silently and asynchronously by nature — background offline sync, billing webhooks, AI calls with real cost attached. When one of those degrades in production, the current answer is to read logs and guess.

## Scope

- OpenTelemetry traces, metrics and logs with OTLP export.
- Instrument ASP.NET Core, EF Core and `HttpClient`.
- Custom metrics for the things that carry cost or risk: AI request count, latency and failure rate; offline sync queue depth and failures; billing webhook outcomes; cache hit ratio for the layer added in 5.13.2.
- Correlate requests through the Blazor circuit.
- Document the exporter setup in `docs/production-runbook.md`.

## Guardrails

- No note content, search terms or personal data in spans or attributes — follow the discipline already established in `SearchService`, which records that a search happened but never the term.
- No BYOK keys or billing secrets in any attribute.
- Sampling configurable; default must not meaningfully affect request latency.
- Disabled by default so self-hosting is unaffected.

## Acceptance criteria

- [ ] Traces for a request span the web, application and database layers.
- [ ] AI, sync, webhook and cache metrics are emitted.
- [ ] No personal data appears in any exported telemetry.
- [ ] Telemetry off by default and documented in the runbook.
