# Add web push notifications
<!-- labels: enhancement,priority: P1,area: workflow -->

## Problem

`ITodayNotificationService` produces in-app banners on the Today screen. Nothing reaches the user when Brainy is closed, which is most of the time. A guided weekly review the user never remembers to open, and an overdue task nobody is told about, are both features that quietly do not work.

Version 6.0.0 already shipped a service worker, a PWA manifest and share-target support, so the delivery infrastructure exists. Push is an increment on it, not a new platform.

## Scope

- Web Push (VAPID) subscription management, keyed per user and per device.
- Reuse the existing `ITodayNotificationService` evaluation rather than inventing a second notification model.
- A small, deliberately boring set of triggers: daily focus nudge, overdue task, weekly review reminder.
- Per-category opt-in and quiet hours honouring the user's timezone via `IUserTimeZoneService`.
- Background dispatch that survives app restarts.

## Guardrails

- Strictly opt-in, off by default, with a one-click unsubscribe.
- Never include note content in a push payload — titles and counts only.
- Frequency-capped. This must stay a calm tool; #292's guardrails rule out gamified nagging.
- A failed or expired subscription is pruned, not retried indefinitely.

## Acceptance criteria

- [ ] A user can subscribe and receive a test notification on desktop and mobile.
- [ ] Quiet hours and per-category opt-outs are respected.
- [ ] Payloads contain no note content.
- [ ] Expired subscriptions are removed automatically.
- [ ] Unsubscribing stops delivery immediately.
